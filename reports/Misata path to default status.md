# Misata Must Prove Realism Before It Dominates

Misata already has the hardest part of a "replace your Faker script" library: a fast, reproducible engine that keeps foreign keys intact and hits declared aggregates exactly. What stands between it and default status is two things, and neither is a missing simulation engine. The first is trust: its default output still looks synthetic, and the tool fails silently in places that matter. The second is distribution: it has almost no verified real-world use. The audit (run against 0.9.6.59; 0.9.6.60 shipped on 2026-09-28, so some bugs may already be fixed) found that **5 of 8 typical script-writer tasks hit serious friction**. Seeding a real Postgres schema failed on CHECK, VARCHAR(n), CHAR(2) and text-key constraints. Mistyped distribution parameters silently produced uniform 0–1000 values. The default e-commerce dataset has **49% of timestamps at exactly midnight**, order amounts that match price × quantity in **0.2%** of rows, and near-uniform product popularity. On adoption, Misata has **69 stars, one contributor, zero issues ever filed by anyone, and 125 releases in about 9.5 months**. The only download figure is the author's own claim of about 350 non-mirror installs a month, against roughly 63M a month for Faker. The open slot is real: no living open-source default exists for schema-aware relational seeding, or for outcome-driven analytics data. Misata can take that slot, and make "realism" its defensible headline, only if it measures realism publicly instead of asserting it. Simulation-style generation is worth adding as a vectorized semi-Markov "process" layer. SimPy should not become a core dependency.

A caveat on evidence. The network proxy blocked pypistats, pepy, ClickPy, libraries.io, Reddit, Hacker News comment bodies, Stack Overflow, and arXiv full text. So no download figure here was verified first-hand, there are no verbatim practitioner forum quotes, and several paper findings rest on abstracts and search snippets rather than full reads. Those limits are flagged below where they matter.

## Ten months in, nobody outside the author is visibly using Misata

The adoption signal is thin by any measure. Misata has **69 stars, 3 forks, 0 watchers and a single contributor with all 450 commits**. The only three PRs ever opened were the maintainer's own release PRs, and **no issue has ever been filed, by an external user or anyone else** ([GitHub API](https://api.github.com/repos/rasinmuhammed/misata); [issues](https://api.github.com/repos/rasinmuhammed/misata/issues?state=all)). Forty-seven of the stars arrived in December 2025, **36 of them on 2025-12-20**. That matches a Show HN that reached HN's day-2 front-page listings and second-chance pool ([Show HN: Misata](https://news.ycombinator.com/item?id=46289055); [stargazers](https://api.github.com/repos/rasinmuhammed/misata/stargazers)). Since then growth has been about 2–6 stars a month. None of the three forks has a commit of its own ([forks](https://api.github.com/repos/rasinmuhammed/misata/forks)). Download data could not be verified. The only figure is the project's own grant application, which claims **about 959 downloads in 30 days, or about 350 excluding mirrors**, as of July 2026 ([foss-united-application.md](https://github.com/rasinmuhammed/misata/blob/main/grant-applications/foss-united-application.md)). Even the 350 is probably inflated. With 56 releases in July 2026 alone ([PyPI JSON](https://pypi.org/pypi/misata/json)), mirror and scanner fetches produce exactly the release-day spikes the application reads as "repeat users". For scale, search snippets put Faker at **63.5M downloads a month**, factory_boy at **22.9M** and polyfactory at **11.7M** ([pypistats Faker](https://pypistats.org/packages/faker); [factory-boy](https://pypistats.org/packages/factory-boy); [polyfactory](https://pypistats.org/packages/polyfactory)).

Public discussion is almost entirely self-authored. There are dev.to and Towards AI posts with titles like "The Best Python Library for Generating Quick Synthetic Data in 2026" ([dev.to](https://dev.to/rasinmuhammed/the-best-python-library-for-generating-quick-synthetic-data-in-2026-5681)), plus SEO comparison pages on misata.studio ([compare](https://www.misata.studio/compare)). Search found no independent write-up, Reddit thread or tutorial. MCP directory listings such as Glama and PulseMCP exist, but they are auto-crawled and show no install counts ([Glama](https://glama.ai/mcp/servers/rasinmuhammed/misata); [PulseMCP](https://www.pulsemcp.com/servers/rasinmuhammed-misata)). The arXiv preprint behind the project has one external reaction, an automated Pith review raising two major objections, and no citing papers that search could find ([arXiv 2606.08736](https://arxiv.org/abs/2606.08736); [Pith](https://pith.science/paper/2606.08736)). GitHub's dependents page, code search and traffic endpoints were all blocked, so hidden internal use cannot be ruled out. Still, a library used in real pipelines almost always collects bug reports, and Misata's empty issue tracker after 125 releases is itself a strong signal.

Four perception problems compound the low numbers.

- **Release churn.** There were up to 5 releases in a single day, and the project uses four-part `0.9.6.x` versions while claiming SemVer and "Production/Stable" ([CHANGELOG.md](https://github.com/rasinmuhammed/misata/blob/v0.9.6.59/CHANGELOG.md#L6); [pyproject.toml](https://github.com/rasinmuhammed/misata/blob/v0.9.6.59/pyproject.toml)).
- **Determinism that holds only within a version.** The RNG stream has changed across releases ([LIMITATIONS.md](https://github.com/rasinmuhammed/misata/blob/v0.9.6.59/LIMITATIONS.md)).
- **Shifting positioning.** In ten months the pitch has moved from "LLM synthetic data engine" to "no model in the data path" to "Instant Sandbox Oracle for AI coding agents" ([PyPI](https://pypi.org/pypi/misata/json)).
- **A bus factor of one.** The faker.js sabotage in January 2022 showed users exactly what that risk looks like ([BleepingComputer](https://www.bleepingcomputer.com/news/security/dev-corrupts-npm-libs-colors-and-faker-breaking-thousands-of-apps/)).

These erode trust more than any single missing feature.

## The default slot is empty, and Misata's engine fits it better than anything alive

Every current default in this space won on distribution, not on technical merit. Faker shipped in 2010 and got wired into pytest, factory_boy and polyfactory ([Faker pytest docs](https://faker.readthedocs.io/en/master/pytest-fixtures.html); [factory_boy](https://factoryboy.readthedocs.io/en/latest/_modules/factory/faker.html)). Mimesis is about 12x faster by its own benchmark and still never displaced it ([Mimesis](https://mimesis.name/latest/about.html)). Faker's weakness is structural: it generates column contents independently and keeps no dependencies between columns ([arXiv 2410.21717](https://arxiv.org/html/2410.21717)). A Faker issue showing a profile with username `michaeladams`, name `Kevin Brown` and email `rollinslisa@hotmail.com` was closed as stale ([faker #1185](https://github.com/joke2k/faker/issues/1185)). Teams therefore fill the gap with hand-written scripts. The Databuddy seed-script PR is a typical example: the team had to add a `--seed` flag after discovering that "two runs with the same arguments produce different data". They also had to add a Markov page-transition table, because independent events made "any funnel… show near-zero, meaningless conversion" ([Databuddy PR #990](https://github.com/databuddy-analytics/Databuddy/pull/990)). Each of those patches is a feature Misata could ship as a built-in.

The dedicated tools for that job have died or stalled.

- **Snaplet** shut down on 2024-08-31 because it "did not reach the necessary adoption levels" ([Supabase](https://supabase.com/blog/snaplet-is-now-open-source)).
- **Neosync** was archived in August 2025 after an acqui-hire ([GitHub](https://github.com/nucleuscloud/neosync)).
- **Synth** has had no push since September 2024 ([GitHub](https://github.com/shuttle-hq/synth)).
- **plaitpy**, the closest analogue to Misata's YAML mode, has been dead since 2018 ([GitHub](https://github.com/plaitpy/plaitpy)).

On the model-based side, SDV moved to BUSL-1.1, a license DataCebo itself says "is not an Open Source license" ([DataCebo](https://datacebo.com/blog/sdv-bsl-license/)). It also needs real data to fit. An SDV user who had only marginal statistics asked to "skip the modeling; generate data from pre-specified distributions" and the request was closed as not planned ([SDV #403](https://github.com/sdv-dev/SDV/issues/403)). That is precisely Misata's cold-start use case. The commercial "train on your data" vendors have consolidated or failed: Gretel went to NVIDIA, Hazy to SAS, and MOSTLY AI ceased operations in March 2026 ([TechCrunch](https://techcrunch.com/2025/03/19/nvidia-reportedly-acquires-synthetic-data-startup-gretel/); [beri.net](https://www.beri.net/article/best-synthetic-data-platforms-real-data-cannot-leave-2026)).

The live competition is elsewhere. **NVIDIA's NeMo Data Designer** (Apache-2.0, 2.3k stars within about a year) offers declarative columns, samplers and LLM-generated columns ([GitHub](https://github.com/NVIDIA-NeMo/DataDesigner); [arXiv 2609.17699](https://arxiv.org/html/2609.17699v1)). **Tonic Fabricate**, from $0 to $29 a month, uses an LLM for text and a JavaScript sandbox for "mathematically rigid fields" ([Tonic](https://www.tonic.ai/blog/tonic-fabricate-vs-claude)). **Seedfast** introspects a live Postgres schema and exposes a one-call MCP tool ([Seedfast](https://seedfa.st/)). And there is the general habit of asking an LLM to write a Faker script. The serious LLM vendors have converged on Misata's architectural bet: deterministic machinery for structure, the LLM only for semantics. Misata's advantages are that it runs locally, is free under MIT, needs no token cost per run, and guarantees exact aggregates. The engine supports this. In the audit it generated 22k FK-correct rows in 0.23 s, byte-identical across reruns, and streamed **10.1M rows to Parquet in 15.5 s at 661 MB peak memory** ([audit script](file:///tmp/claude-0/-home-user-misata/c1151dc1-f1ea-5128-8eaa-843521027c8e/scratchpad/t/c.py)). The test suite passed **2,144 tests**. Its declaration language covers about 24 certified primitives, including outcome curves, group shares, lifecycles, SCD2, event logs and declared missingness ([schema.py](https://github.com/rasinmuhammed/misata/blob/v0.9.6.59/misata/schema.py#L344); [LANGUAGE.md](https://github.com/rasinmuhammed/misata/blob/v0.9.6.59/LANGUAGE.md#L516)). Nothing else in open source does this. The blockers sit around the engine, not inside it.

## Five of eight script-writer tasks broke on the paths users hit first

The riskiest path is "seed my existing database", because real DDL is full of constraints. `from_ddl` dropped CHECK constraints, inline UNIQUE, and CHAR/VARCHAR lengths; the parser skips table-level constraint lines entirely ([ddl.py:198](https://github.com/rasinmuhammed/misata/blob/v0.9.6.59/misata/ddl.py#L198)). Against SQLite, seeding failed on `CHECK constraint failed: status IN (...)` and then on non-unique emails. Against Postgres 16 it failed three times in a row:

1. A VARCHAR(12) column was overrun.
2. A `country_code CHAR(2)` column was filled with "Australia".
3. A text primary key `sku` was filled with prose ("Customer requested expedited processing yesterday afternoon. 2"), which then broke the FK sampling.

Seeding is also non-atomic, because each batch commits separately. A failed run therefore leaves partially seeded tables, and the next run refuses to proceed ([db.py:336-396](https://github.com/rasinmuhammed/misata/blob/v0.9.6.59/misata/db.py#L336)). `--truncate` fails on Postgres whenever foreign keys exist, because it issues TRUNCATE without CASCADE ([db.py:303-312](https://github.com/rasinmuhammed/misata/blob/v0.9.6.59/misata/db.py#L303)). A relative `sqlite:///dev.db` URL resolves to `/dev.db` at the filesystem root, and that is the CLI's own help example ([db.py:315-325](https://github.com/rasinmuhammed/misata/blob/v0.9.6.59/misata/db.py#L315)). Two audit runs left empty files at `/b.db` and `/b3.db` in the container, which still need manual removal.

The second problem is silent wrong output, which is the worst failure for a library that sells "declare it and it holds". `{"distribution": "poisson", "lamda": 7}` (a typo) and `{"distribution": "gumbel"}` (unsupported) both raised no error and silently produced uniform values from 0 to 1000. Numpy-style `mean`/`std` for a lognormal were also accepted silently, and gave a mean of 3.49 where the documented `mu`/`sigma` give 46 ([audit script a2.py](file:///tmp/claude-0/-home-user-misata/c1151dc1-f1ea-5128-8eaa-843521027c8e/scratchpad/t/a2.py)). Object and array columns silently became business-note prose. The root cause is that `distribution_params` is an untyped dict ([schema.py](https://github.com/rasinmuhammed/misata/blob/v0.9.6.59/misata/schema.py#L41)). Recent commits confirm the pattern: 0.9.6.59 fixed a `__group_shares__` nesting that "used to silently generate a completely different, wrong distribution with no warning".

The third problem is the escape hatch. When a declaration cannot express what a user needs, Misata offers only `custom_generators`, and that hatch is too thin to replace a script.

- It is available only from `generate_from_schema`, not from YAML, the CLI, the story path or `seed_database`.
- Its `context` holds only parent primary keys, not parent attributes, so a child column cannot read the customer's `country` ([simulator.py:260](https://github.com/rasinmuhammed/misata/blob/v0.9.6.59/misata/simulator.py#L260)).
- It passes no RNG, so users have to manage reproducibility themselves.
- A per-row function on an early column silently returns all zeros ([simulator.py:1506-1509](https://github.com/rasinmuhammed/misata/blob/v0.9.6.59/misata/simulator.py#L1506)).
- There are no table-level post-hooks and no plugin entry points.

The practitioner evidence asks for exactly these: callables with access to parent and sibling rows, per-table hooks, and the ability to bring your own DataFrame for one table ([SDV #2545](https://github.com/sdv-dev/SDV/issues/2545)). An HN thread on config formats sums up the tension: for complex logic, "it's better to have real if-statements and for-loops" ([HN 31966122](https://news.ycombinator.com/item?id=31966122)). A declarative core only replaces scripts if its Python hooks are first-class.

The rest is friction rather than breakage, and it adds up.

- **In-memory generation is 10x slower than streaming at 10M rows** (154 s against 15.5 s), because tables grow through a `pd.concat` per 10k-row batch ([__init__.py:145-149](https://github.com/rasinmuhammed/misata/blob/v0.9.6.59/misata/__init__.py#L145)).
- **`generate_stream` accepts only a story**, so a hand-built schema cannot be streamed through the public API.
- **`import misata` takes about 1.7 s** because about 60 submodules load eagerly.
- **The public API is sprawling.** It exports 156 names (one class is shadowed by a duplicate import), the CLI has 26 commands, and the shadowed `validate` CLI command makes the DB validator dead code ([cli.py](https://github.com/rasinmuhammed/misata/blob/v0.9.6.59/misata/cli.py#L1362)).
- **Nested JSON is unsupported.**
- **There is no Polars support.**
- **The story parser handles novel domains poorly.** It refuses honestly ([audit script h.py](file:///tmp/claude-0/-home-user-misata/c1151dc1-f1ea-5128-8eaa-843521027c8e/scratchpad/t/h.py)), but it ignored "40 stores… 20000 receipts" and built generic e-commerce instead. A request for "order items" produced no `order_items` table and no warning.

## The default dataset fails the dashboard sniff test

Realism is the claim the user wants to lead with, so it deserves the hardest look. At the column level, Misata's output is better than Faker's. Name and email agree. Prices end in .99 and .95. Ratings are J-shaped (mean 4.04). Status and payment mixes are plausible. At the dataset level, the default story dataset (`misata.generate("An ecommerce store with 5000 customers…", seed=3)`) shows the tells practitioners name ([audit script real.py](file:///tmp/claude-0/-home-user-misata/c1151dc1-f1ea-5128-8eaa-843521027c8e/scratchpad/t/real.py)):

| Tell | Misata default output | What real data looks like |
|---|---|---|
| Time of day | **49.4% of order timestamps at exactly 00:00:00**; the rest peak at 01:00–03:00 and fall to 23:00 | Evening peak for e-commerce |
| Day of week | 2,098–2,205 orders per weekday (flat) | Clear weekday/weekend shape |
| Line economics | `amount = price × qty` in **0.2%** of rows; 45% of orders cost less than one unit | Totals equal the sum of line items |
| Popularity | Top 10 of 1,000 products = **1.74%** of orders | Pareto / Zipf |
| Customers | Max 10 orders per customer, no "whales" | Heavy-tailed activity |
| Category | Price medians 56–79 in every category | Category drives price band |
| Value pools | 120 distinct names across 1,000 products; 8 email domains at 12–13% each | Gmail-dominated, diverse catalog |
| Locale | Vikram Kapoor lives in France; Japanese names get `dorothy.brown2@outlook.com` | Name, country and email agree |
| Mess | Zero nulls, zero duplicates by default | Some nulls and dupes always |

A data analyst would notice each row of that table in minutes. They match the general literature on why synthetic data looks fake. Uniform money amounts give a leading digit of 1 about 11% of the time, where Benford's law gives about 30% ([hackernoon](https://hackernoon.com/faker-is-not-synthetic-data-where-mid-sized-schemas-break)). Uniform fan-out "makes the planner always right" ([django-data-shape](https://github.com/Artui/django-data-shape)). Benchmark generators "make oversimplified assumptions… uniform distribution and independence" ([VLDB 2022](https://www.vldb.org/pvldb/vol15/p752-zhu.pdf)). Two more defects add to these. The yearly and weekly seasonality code computes `sin((t − peak_offset)·2π/period)`, which puts declared peaks a quarter period late: a December peak lands in February–March, and a Saturday peak lands on Monday ([timeseries.py:168-180](https://github.com/rasinmuhammed/misata/blob/v0.9.6.59/misata/timeseries.py#L168)). The story path also maps any "weekend" phrase to a Tuesday peak ([timeseries.py:298-305](https://github.com/rasinmuhammed/misata/blob/v0.9.6.59/misata/timeseries.py#L298)). Cross-column correlation exists only as 12 hard-coded keyword rules ([__init__.py:155-168](https://github.com/rasinmuhammed/misata/blob/v0.9.6.59/misata/__init__.py#L155)). LIMITATIONS.md concedes US-flavoured priors and free text with a "template rhythm a careful reader can spot". The important nuance is that Misata's *declared* statistics are where it is strongest. The realism risk is concentrated in the *undeclared defaults*, which are what a newcomer sees first. The audit did not test `mimic`, capsules or a strict realism mode, and any of those could improve these numbers.

### How to claim realism credibly without source data

Every standard realism metric is reference-based. SDMetrics compares column shapes (KS and TV complements) and column-pair trends ([SDMetrics](https://docs.sdv.dev/sdmetrics/data-metrics/quality/quality-report)). Synthcity uses α-precision and β-recall ([NeurIPS 2023](https://papers.neurips.cc/paper_files/paper/2023/file/09723c9f291f6056fd1885081859c186-Paper-Datasets_and_Benchmarks.pdf)). Other approaches are TSTR utility ([arXiv 2404.14445](https://arxiv.org/html/2404.14445v2)) and classifier detection. SyntheRela's relational detection, which enriches parent rows with child aggregates, found that "no method is able to synthesize a dataset that is indistinguishable from original data" ([arXiv 2410.03411](https://arxiv.org/pdf/2410.03411)). A tool that never sees real data cannot report these numbers in the usual way. Value-level tools (Faker, Mockaroo, Snaplet seed, Synth, ShadowTraffic) all claim "realistic" or "production-like" data and publish no metric. Misata's own paper is careful to claim *conformance*, and calls the two axes "orthogonal" ([arXiv 2606.08736](https://arxiv.org/abs/2606.08736)). A realism headline would therefore be a new, unproven claim. The open question is which kind of evidence a skeptical reader would accept.

The no-source projects that made credible realism claims did it with domain grounding plus external, blinded validation. Synthea was validated against published clinical quality measures, with its gaps documented openly ([BMC Med Inform 2019](https://link.springer.com/article/10.1186/s12911-019-0793-0)). CMU's Synthetic Hospital (September 2026) built 1,268 patients from public material, and blinded physicians told its records apart from real charts at **53%, near chance** ([arXiv 2609.30027](https://arxiv.org/abs/2609.30027)). The cautionary cases show what an audit has to catch. PaySim fraud is identified 97.8% of the time by a single equality, `amount == oldbalanceOrg` ([leakage audit](https://github.com/namanphogat0003-commits/fraud-detection-pipeline)). Synthea generated 100% of type-2 diabetes patients with an amputation ([OHDSI 2024](https://www.ohdsi.org/wp-content/uploads/2024/10/41-Wagner-Evaluating_Synthea-Clair-Blacketer.pdf)).

Combining the two gives a three-layer claim Misata can defend.

1. **A built-in, reference-free realism report on every run.** It would score checkable invariants:
   - Benford conformance on money columns;
   - Zipf or long-tail fan-out on foreign keys;
   - diurnal, weekday and seasonal shape, anchored to "now";
   - cross-column coherence (name↔email↔country↔phone format, category↔price);
   - rule consistency (totals equal line sums, status agrees with dates);
   - value-pool diversity (distinct ratio, no value above x%);
   - a declared mess budget;
   - a "single-feature label leakage" check of the PaySim kind.

   Each property would be tagged **exact**, **calibrated** or **emergent**, so realism features never blur the conformance guarantee.
2. **A published realism benchmark against held-out real data that Misata never sees.** Take public relational datasets with known schemas. Generate from only a story, or a schema plus a handful of public aggregates. Then report SDMetrics shapes and pair trends, a SyntheRela-style detection AUC, an LLM-discriminator rate, and a small blinded human test, all against the real holdout. Learned synthesizers *fitted on that data*, such as SDV, should be the comparison. The LLM discriminator must use several models, because one 2026 study saw detection swing from 0% (LLaMA) to 100% (Gemini) on the same synthesizers ([arXiv 2606.09865](https://arxiv.org/abs/2606.09865)). The honest headline is not "indistinguishable". It is "Misata, with zero access to the data, lands within X of tools that trained on it".
3. **Use-case realism presets** (demo, load, test, ml, eval). Each use case needs a different kind of realism. Demos need stories that "hold together". Load tests need skew and clustering. dbt tests need targeted edge cases. Agent and text-to-SQL evals need valid, noisy, reproducible databases. SynSQL showed fresh databases cut text-to-SQL accuracy by 3–14% and changed model rankings ([arXiv 2604.27261](https://arxiv.org/html/2604.27261)).

No general-purpose no-source open-source tool publishes numbers like these today, so Misata would be first. Without them, "realistic" puts Misata in the same bucket as Mockaroo's marketing copy.

## Simulation: build a process kernel, not a SimPy dependency

Simulation is genuinely required only where the output metric emerges from interaction. Examples are queue waits and utilization under finite capacity, contagion, AML ring patterns, and patient trajectories. The tools serving those needs are niche: Mesa has 3.9k stars, Synthea 3.4k, PM4Py 1.0k, and the Prosimos BPS engine 14 ([Mesa](https://github.com/mesa/mesa); [Synthea](https://github.com/synthetichealth/synthea); [Prosimos](https://github.com/AutomatedProcessImprovement/Prosimos)). Their most-used outputs are pre-generated datasets such as PaySim on Kaggle, not the simulators themselves ([Kaggle paysim1](https://www.kaggle.com/datasets/ealaxi/paysim1)). What Misata's audience lacks is *sequence and timing realism*: sessions, funnels, journeys, ticket lifecycles. That is the Databuddy fix and ShadowTraffic's `stateMachine` ([ShadowTraffic](https://docs.shadowtraffic.io/functions/stateMachine/)). Misata's current lifecycle draws each step's dwell time uniformly on (0, `max_days_per_step`], with one global 30-day bound. It has no per-transition distributions, no history-dependent loops and no arrival process, and the audit's clickstream story produced inverted relationships and no session structure ([audit script f.py](file:///tmp/claude-0/-home-user-misata/c1151dc1-f1ea-5128-8eaa-843521027c8e/scratchpad/t/f.py)). SimPy is a poor fit as a core dependency. It is MIT-licensed but thinly maintained, with a 2.5-year release gap ([PyPI simpy](https://pypi.org/project/simpy/)). It runs single-threaded, one Python generator per process, and one user reported a 60M-event simulation taking "a couple of hours" ([GitLab #112](https://gitlab.com/team-simpy/simpy/-/work_items/112)). An imperative event loop would also break Misata's anchored per-column RNG streams and edit-stability guarantees.

The better design is **allocate, then simulate**. Case counts per period, terminal-state mixes, variant frequencies and rework rates stay exact through the existing largest-remainder allocation. Only the timing inside those fixed counts is sampled, through a vectorized semi-Markov kernel: per-transition dwell distributions, bounded loops, and non-homogeneous Poisson arrivals driven by declared curves. Capacity-constrained waits can come later as an optional `resources:` block. That block would use the Lindley recursion for single-server queues and a heap pass for multi-server queues (standard queueing theory, not benchmarked here), and it would report waits as *emergent* rather than guaranteed. Synthetic-population practice, fitting marginals with IPF and then running agent simulation, is the established precedent for this split ([JASSS 2021](https://www.jasss.org/24/2/5.html)). Two underserved niches follow directly. The first is XES/OCEL 2.0 event logs with exact ground truth for process-mining research, where evaluation logs are still built by hand ([Zenodo 22140119](https://zenodo.org/records/22140119); [OCEL 2.0](https://arxiv.org/pdf/2403.01975)). The second is fraud/AML typologies with exact prevalence and an audited absence of PaySim-style leakage.

## Prioritized gap list

Effort estimates assume the current single maintainer working with the existing codebase. They are judgment calls, not measurements. Items marked "may be fixed in .60" should be re-checked against 0.9.6.60 first.

| # | Gap | Why it blocks default status | Effort |
|---|---|---|---|
| **P0-1** | **Strict spec validation**: typed per-distribution parameter models; error on unknown distribution, misspelled key or unsupported type (`object`/`array`); no silent `normal`/`['Unknown']` fallbacks | Silent wrong output breaks the "declare it and it holds" promise | 3–5 days |

## Conclusion

Misata's problem is not a missing primitive. It is that its strongest asset, exact conformance, is invisible in the default output, while its weakest points (silent fallbacks, constraint-blind seeding, midnight timestamps) are the first things a skeptical user sees. That ordering is backwards for a tool trying to become a default. Fixing the P0 list mostly means *removing* surprises rather than adding features, which is roughly two to three months of focused work. That suggests freezing new declarations until it is done.

On realism, the strategic opening is that nobody in the no-source category measures realism, so the first project to publish a held-out, multi-judge realism benchmark gets to define what "realistic synthetic data" means. Misata is unusually well placed to do this, because the exact/calibrated/emergent vocabulary lets it make a realism claim without diluting its conformance claim. The adoption picture is the larger uncertainty. Download and forum data were unreachable here, so a verified pypistats series and a first external issue or dependent repo are the evidence that would show whether any of this is working.
